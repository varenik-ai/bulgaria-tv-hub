# Bulgaria TV Hub — Эталон v1.0

## Что работает
- Один экран (v22, раскладка мини-аппа tv-indonesia): плеер `#pl` сверху, прилипает; под ним поиск, категории и список каналов
- Fullscreen: Android container.requestFullscreen(), iOS video.webkitEnterFullscreen()
- После выхода из fullscreen iOS: stopStream() + init()
- Фоновый звук Android: audio-bg (muted=true, играет для сессии)
- Фоновый звук iOS: Media Session API
- v24: полноэкранный режим Telegram при запуске НЕ включаем (как в tv-indonesia: только `tg.expand()`). В нём кнопки Telegram «Назад»/«Закрыть» висят поверх плеера на iPhone
- v26: запуск в Telegram 1:1 как в tv-indonesia и russia-tv-hub: только `tg.ready(); tg.expand(); tg.setHeaderColor('secondary_bg_color')`. Нет `disableVerticalSwipes`, своего цвета шапки/фона, отступа `--tg-safe-top` и выхода из полноэкранного режима при запуске (v25 убран). Если мини-апп всё равно открывается во весь экран — причина вне страницы (настройка бота в BotFather или старая версия)
- Safe area: с v26 не используется (как в tv-indonesia)
- Звук (v23): кнопки «Звук» нет. Звук включается при нажатии на канал, выключается в системной панели видео (`controls`); изменения из панели запоминаются (`volumechange` → `userUnmuted`/`_soundWanted`), свои изменения код делает только через `setMuted()`
- PiP: только PC (requestPictureInPicture), скрыт на iOS/Android
- Закрыть плеер: ✕ (`#back-btn`) и системная кнопка Telegram «Назад» (`tg.BackButton`), список остаётся
- Адаптивный поток: index.m3u8 (576p-1080p)
- isIOS(): включает Telegram.WebApp.platform === "ios"

## Критичные правила
- video вне overlay (не гаснет при auto-hide)
- НЕ вызывать Telegram.WebApp.requestFullscreen() И container.requestFullscreen() одновременно
- .ts для iOS — напрямую (UA: applecoremedia/cfnetwork/darwin)
- .ts для Android — через Vercel (CORS блокирует прямой доступ)
- В начале loadStream `userUnmuted=_soundWanted`; если браузер не дал играть со звуком — `_playWithFallback()` играет без звука
- video.muted=true перед play() в MANIFEST_PARSED
- Кнопка AirPlay (v23, как в tv-indonesia): одно нажатие сразу открывает выбор ТВ, если у видео есть `webkitShowPlaybackTargetPicker`. Наличие `WebKitPlaybackTargetAvailabilityEvent` НЕ проверять: в Telegram на iPhone его нет, а выбор ТВ работает (из-за этой проверки кнопка уводила на сайт). Без выбора ТВ — подсказка `t.airHint` и страница канала. Двухшагового режима и `t.airAgain` больше нет

## Что добавлено по эталону v1.3 (Bulgaria v9)
- Сетка в 2 колонки, синяя кнопка «Каналы» первой в панели, кнопка 📲 AirPlay (только iOS, если WebView отдаёт AirPlay API), выбор качества ⚙ (hls.js, `localStorage rtv_quality`).
- Повторные подключения только через `_scheduleInit` (backoff до 30 с, после 6 неудач «Канал временно недоступен»); после 2 неудач `init()` просит у воркера запасной путь `&proxy=1`.
- Режим CORS-only: `/stream` отдаёт прямую ссылку на CDN glebul.com (все 38 каналов отдают `Access-Control-Allow-Origin: *`), `/proxy` оставлен как запасной и пускает только разрешённые хосты.
- Android: `audio-bg` играет `SILENT_WAV`, второй hls.js не поднимается. Авторефреш токена удалён.
- **Сторож зависания** (`setInterval` 5 с): реконнект, если нет прогресса кадров 9 с, нет буфера 12 с, либо `currentTime` стоит 18 с (30 с до первого кадра, `START_GRACE_MS`); сначала дешёвый перескок разрыва `_tryNudgeGap()`. Реконнект только через `_watchdogReconnect`.
- **Звук после реконнекта:** `_soundWanted` ставится кнопкой «Включить звук», `_restoreSound()` вызывается после `play()`; если браузер не дал звук без жеста — через 1,5 с возврат в режим без звука. Смена канала сбрасывает флаг.
- Пока не перенесено: нативное качество iOS (`/stream-q`), профилактический реконнект (нужен только каналам cinerama.uz, у Bulgaria таких нет).

## Трансляция на ТВ (по эталону russia-tv-hub, Bulgaria v15)
- **iOS (в том числе внутри Telegram):** блок AirPlay скопирован из эталона 1:1. Кнопка «📲 AirPlay» видна у каждого канала (`airVis` не зависит от наличия AirPlay API). Если API есть: первое нажатие на `blob:`-источнике (hls.js) ставит `_forceNative = true`, текст «📲 AirPlay ▶», канал перезапускается на нативном HLS; следующее нажатие открывает `webkitShowPlaybackTargetPicker()`. Если API нет (WebView Telegram) — страница канала открывается во внешнем Safari: `window.open(SITE_URL + '#<id>')`, запасной путь `tg.openLink`.
- **`_forceNative` не сбрасывается** при смене канала (как в эталоне), а в `loadStream` условие `_forceNative && isIOS() && canPlayType('application/vnd.apple.mpegurl')`.
- **Android/Desktop в Telegram:** с v30 кнопки «📺 На ТВ» нет (Cast из WebView невозможен, а она лишь открывала сайт). Вне Telegram Cast работает через `cast.js`
- **Google Cast** (`cast.js`) работает только вне Telegram (Chromium): Default Media Receiver, `loadMedia` с прямой ссылкой на плейлист; во время трансляции локальное видео стоит, сторож зависания отключён (`window.__castActive`). `?castdebug=1` показывает состояние.
- Кнопки «Смотреть на сайте» нет (решение владельца). `<meta name="referrer" content="no-referrer">` есть.
- **Не проверено на реальном ТВ.** Проверено подставными окружениями: iOS без AirPlay API, iOS с API (два шага, `_forceNative` сохраняется при смене канала), Android в Telegram.
- Не перенесено: фиксация качества для нативного iOS (`/stream-q`).

## AirPlay: выводы тестов на реальном ТВ (Samsung), v17
- **Звук обязателен.** Заглушённое (`muted`) видео iOS не передаёт на ТВ (журнал страницы `airtest.html`: `webkitCurrentPlaybackTargetIsWireless=false`). Поэтому при нажатии «📲 AirPlay» приложение включает звук в самом жесте (`video.muted=false`, `_soundWanted=true`), а `loadStream` не глушит видео обратно, пока включён режим AirPlay.
- **ТВ сам скачивает поток по своей сети, без VPN телефона.** Тест скорости с телефона без VPN: GitHub Pages — быстро, Cloudflare (любой `workers.dev`, в том числе мой воркер) и `glebul.com` — зависание >20 с; с VPN всё быстро. Те же сегменты на Pages ТВ играет (контроль), через Cloudflare и с glebul нет. Эталон работает, потому что его сегменты лежат на серверах, доступных из этой сети; воркер отдаёт ему только плейлисты (маленькие файлы проходят).
- **Вывод:** AirPlay-видео на этом ТВ с источником glebul возможно только если у самого ТВ есть доступ к glebul/Cloudflare (VPN на роутере или раздача интернета с телефона, у которого включён VPN). Кодек, порядок NAL-блоков, заголовки и Range не при чём (проверено: оригинальные сегменты со статики идут). Устарело: решение без VPN см. в разделе про ro.glebul.com.
- Прокси сегментов через воркер для ТВ не даёт ничего: AirPlay использует прямую ссылку (`stream` JSON), как в v15.
- Тестовые материалы удалены: `airtest.html`, `airtest/`, маршруты `/airtest`, `/ts/`, `/tvtest`, хост `varenik-ai.github.io` в `ALLOWED_HOSTS`, воркер `bg-relay-test`. При необходимости их можно достать из истории git.

## Трансляция на ТВ из РФ: узел ro.glebul.com, v19
- ТВ сам скачивает поток без VPN телефона. Из домашней сети в РФ cdn3/cdn11/mx86.glebul.com (OVH) зависают на ~16 КБ, а ro.glebul.com (85.204.107.233) отдаёт сегменты целиком.
- Токены `e=`/`hash=` совместимы между узлами и не привязаны к IP: на ro работают все 65 каналов из `relay/main.ts`, замер `curl --interface en0`.
- v23: на iPhone `_forceNative = isIOS()` — канал всегда в нативном плеере и с ro (`tvUrl`), поэтому выбор ТВ не требует второго нажатия. Запасной путь через воркер на iPhone разрешён, пока видео не на ТВ. Не проверено, как ro открывается не из России.
- `tvUrl()` в `index.html` до v23 переводил адрес на ro только для AirPlay (`_forceNative`) и Cast. В обычном просмотре адрес прежний: ro закрыт для IP Cloudflare, поэтому воркер по-прежнему отдаёт mx86.
- `relay/` больше не подключён к приложению. Это запасной вариант, если ro перестанет проходить.
- v20: сторож зависания не работает, пока `webkitCurrentPlaybackTargetIsWireless` = true. Кадры в это время показывает ТВ, счётчик на телефоне стоит, и сторож сбрасывал поток примерно каждые 10 с (на ТВ это выглядело как буферизация).
- SD-каналы (28 из 65, 720×576, SAR 64:45) на Samsung по AirPlay идут не на весь экран. `RESOLUTION=1024x576` в master-плейлисте не помогает (проверено на ТВ, The Voice), настройка размера картинки на ТВ заблокирована на 16:9. Остаётся только перекодирование на своём сервере.

## Механика как в tv-indonesia, v23
- Нет кнопки «Звук»: у видео системная панель (`controls`), звук сразу при выборе канала.

## AirPlay по возможности, а не по устройству, v27
- `_airCapable = isIOS() || (есть video.webkitShowPlaybackTargetPicker && нативный HLS)`. Там «📲 AirPlay», `_forceNative = _airCapable` (нативный плеер и `tvUrl`).
- Так AirPlay получают Mac в Telegram (если его WebView даёт выбор ТВ) и Safari на Mac. Без выбора ТВ в Telegram никакой кнопки ТВ нет (v30), в Chrome вне Telegram — Cast
- В Safari на Mac из-за нативного плеера нет кнопки качества. Проверено только на имитациях: есть ли выбор ТВ в Telegram для Mac — не проверено.

## Все надписи на языке интерфейса, v28
- Язык: `language_code` пользователя Telegram, иначе язык браузера (`getLang()`), 8 языков. Telegram передаёт язык только при запуске.
- Категории — `CAT_I18N[lang][индекс группы]` (эмодзи берётся из `label`), описания каналов — `DESC_I18N[болгарское описание][индекс языка]`; болгарский — из `CHANNEL_GROUPS`. Новый канал или новое описание: добавить перевод в `DESC_I18N`.
- Надписи из вёрстки (метка «НА ЖИВО», плашка аудиорежима, подзаголовок), экран блокировки и меню качества берутся из `T` (`live`, `audioPill`, `tagline`, `qAuto`, `mbps`). Зашитого текста в вёрстке быть не должно, кроме логотипа и названий каналов.

## Узлы источника меняются: сбои 25.11.2026, v29 + воркер glebul-v14
- Источник (seirsanduk → glebul.com) сам выбирает узел: `cdn11`, `mx86`, `us`, `uk`, `ro`. Узлы бывают мертвы или недоступны из РФ без VPN. Замер 25.11.2026: `cdn11` не отвечал ни у кого (из дома «отказ», через VPN обрыв, из Cloudflare 521); `us` из дома без VPN не открывался; `ro` не отвечал на плейлисты ни дома, ни через VPN; `mx86` и `uk` работали везде.
- Воркер (`getStreamUrl`): `cdn11` → `mx86`, `us` → `uk` (токены `e=`/`hash=` и пути те же), `ro` → `mx86` (как раньше). Проверено: 14 из 14 каналов с cdn11 на mx86 и 13 из 14 каналов с us на uk отдают полные сегменты из дома и через VPN.
- Страница: `USE_RO = false`, `tvUrl()` ничего не подменяет, ТВ берёт ту же ссылку, что телефон. ro (v19) оставлен под флагом: включать, только если провайдер снова начнёт обрезать mx86/uk для ТВ и ro при этом отвечает. Урок v23: нельзя делать просмотр зависимым от одного узла (`_forceNative` на iPhone вместе с ro ломал все каналы, когда ro замолчал).

- Проверка при сбоях: `curl -s -A AppleCoreMedia/1.0.0 "<url из /stream?channel=ID>"`, затем плейлист и один сегмент, и из дома (`--interface en0`), и через VPN. Узел, который проходит в обоих местах, и есть рабочий.

## Автоматическая проверка серверов, v30
- `scripts/check_streams.py`: для каждого канала берёт ссылку у воркера, скачивает плейлист и один сегмент (две попытки на шаг). Только стандартная библиотека и curl. Результат: таблица по узлам и каналам, `status.json`.
- Код выхода 1, если не играют ≥ 2 канала, есть мёртвый узел (≥ 2 канала на нём и ни одного рабочего) или воркер не отвечает. Один неисправный канал — только предупреждение.
- `.github/workflows/check-streams.yml`: раз в 3 часа и вручную. При сбое GitHub присылает письмо о неудачном запуске, таблица лежит в сводке запуска, `status.json` в артефактах 7 дней.
- GitHub считает из США: узел, недоступный из РФ (как `us.glebul.com` 25.11.2026), так не поймать. Для РФ запускай дома: `python3 scripts/check_streams.py --iface en0` (macOS, мимо VPN).
